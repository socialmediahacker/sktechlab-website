# Home page 500 fix

## What will change
- Make the five public home-page data requests independent, so one temporary backend failure cannot return a blank 500 page.
- Provide safe empty/default values for categories, templates, demos, reviews, and site settings when a request fails.
- Keep automatic retries/refetching so real content returns when the backend recovers.
- Confirm the reported `utils.ts` type error against the current source and generated type-check output.

## Verification
- Run the TypeScript checker to confirm there is no current number-to-string error.
- Request both `/` and the `__lovable_load_id` URL and confirm HTTP 200.
- Check the latest build/runtime logs after the change.

## Technical details
The current route uses one `Promise.all`; any rejected public query rejects the entire route loader. The fix will isolate each preload and seed its query cache with a shape-compatible fallback rather than allowing the page route to fail.
